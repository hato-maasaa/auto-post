# プロダクト仕様書: One Source Two Post Dashboard

## 1. ツールのコンセプト
**「ワンソース・ツーポスト (One Source, Two Posts)」**
ベースのアイデアを1回入力するだけで、note用の“売れる記事”とX用の“バズ狙いポスト”をAIが自動生成し、投稿まで完結させるダッシュボードです。

*   **Core Value**: 普段の「note書く→Xにも告知文考える→別タブ往復してコピペ・投稿」という面倒な作業時間を大幅に削減します。
*   **仕組み**:
    1.  アイデアを1回入力する。
    2.  AIがnote記事とXポストを自動生成する。
    3.  1画面で確認・修正し、ボタン一つで各プラットフォームへ投稿する。

## 2. ユーザーフロー (利用イメージ)
1.  **ダッシュボードを開く**: ローカルのNext.jsアプリを起動します。
2.  **フォームに入力**: 以下の要素をざっくり入力します。
    *   テーマ / タイトル案
    *   想定読者
    *   伝えたいポイント
    *   売りたいもの（あれば）
3.  **コンテンツ生成**: 「コンテンツ生成」ボタンを押下します。
    *   note用の長文記事 (Markdown)
    *   X用ポスト文 or スレッド案
    *   これらが画面下部に生成されます。
4.  **微修正**:
    *   その場でエディタを使って修正します。
    *   X文字数カウンターなどで長さをチェックします。
5.  **noteに投稿**: 「noteに投稿」ボタンを押下します。
    *   Playwrightが裏で自動的にnote編集画面を開き、タイトル・本文を入力して「下書き保存」または「公開」まで実行します。
6.  **Xに投稿**: 「Xに投稿」ボタンを押下します。
    *   API経由で即時投稿されます。
7.  **ログ確認**: 投稿ログで履歴（日時、タイトル、URL）を確認します。

## 3. 機能構成 (MVP)

### A. ネタ入力フォーム
*   タイトル/テーマ
*   ターゲット読者
*   要点・箇条書き
*   トーン選択（ラフ / 丁寧 / エモい など）

### B. AIコンテンツ生成
*   **noteエリア**: 長文記事生成 (Markdown/HTML)
*   **Xエリア**: 短文ポスト生成 (単発 or スレッド)
*   それぞれのエリアに独立して表示し、比較・編集しやすくする。

### C. エディタ機能
*   **note側**: Markdownプレビュー付きのリッチテキスト（簡易版）
*   **X側**: 文字数カウンター、140字超え警告、スレッド分割表示

### D. 投稿機能
*   **X連携**: API (POST /2/tweets) を使用して直接投稿。
*   **note連携**: Playwrightを使用したブラウザ自動操作。
    *   ログイン済みセッションの利用
    *   新規投稿画面への遷移と入力
    *   「公開」または「下書き保存」の実行

### E. 投稿ログ
*   投稿日時の記録
*   noteタイトル、XのURLなどの一覧表示

## 4. 将来的な拡張性 (Nice-to-Have)
*   **複数テンプレート**:
    *   note: 「ストーリー型」「HowTo型」「失敗談」など
    *   X: 「フック強め」「学び系」「自虐ネタ」など
*   **A/Bパターン生成**: Xの文言を2案生成し、ワンクリックで選択できる機能。
*   **プロンプト管理画面**: UI上から使用するプロンプトを調整可能にする機能。

## 5. 記事作成機能のシンプル仕様（v3）

### 5-1. 入力は「3ステップ＋任意オプション」

ユーザーが触るメインの入力はこの4つです：

1.  **ざっくりネタ入力（必須）**
2.  **目的プリセット（1クリック）**
3.  **雰囲気プリセット（1クリック）**
4.  **任意オプション**
    *   参考にしてほしいURL
    *   文章に盛り込んでほしいテキスト

---

### 5-2. 各入力項目の仕様

#### ① ネタ入力（必須）
*   **項目名**: ネタ / 伝えたい内容
*   **UI**: 大きめのテキストエリア1つ
*   **説明文（例）**:
    > ざっくりでOKです。「今日の学び」「体験談」「伝えたいこと」を自由に書いてください。
*   **備考**: ユーザーはここに **ほぼ自由記述** でOK。
    *   （例）「フリーランス3年目で、営業の大事さに気づいた話を書きたい」など。

---

#### ② 目的プリセット（1クリック）
*   **項目名**: この記事の目的
*   **UI**: ボタン or チップ（どれか1つ選択）
*   **候補例**:
    *   **認知をとりたい**（ゆるい読み物）
    *   **学びを届けたい**（HowTo / 解説）
    *   **実績・権威づけをしたい**（事例・数字多め）
    *   **商品・サービスを売りたい**（セールス寄り）
*   ※ 未選択時は「認知＋学び」をデフォルトとする。

---

#### ③ 雰囲気プリセット（1クリック）
*   **項目名**: 文章の雰囲気
*   **UI**: カード型の選択（どれか1つ）
*   **候補例**:
    *   **ラフでフレンドリー**: ため口寄り。「正直〜なんですよね」みたいな距離感近め
    *   **丁寧で落ち着いたビジネス寄り**: 敬語で論理的に説明するトーン
    *   **ストーリーっぽくエモめ**: 体験談ベースで感情も交えて語る
    *   **マニアック解説（オタク寄り）**: 技術・ノウハウをガッツリ深掘り

---

#### ④ 任意オプション
2つのサブ項目をまとめます。（「▼ 詳細オプション」内に入れても可）

##### ④-1. 参考URL
*   **項目名**: 参考にしてほしいURL（任意）
*   **UI**:
    *   URL入力欄（1行テキストボックス）
    *   「＋」ボタンで複数追加もできるようにしておくと拡張性○（必須ではない）
*   **説明文（例）**:
    > 雰囲気や構成を参考にしてほしい記事があれば、URLを貼ってください。
    > 例）過去の自分のnote、他人の記事、ブログなど
*   **AI側の扱い（仕様）**:
    *   URLそのものは「直接スクレイピング」まではしない前提。
    *   プロンプト上は：「以下のURLの記事の、雰囲気・構成を参考にしてください」と伝える用の情報として使う（将来的にスクレイピング対応可能な設計にしておく）。

##### ④-2. 必ず盛り込んでほしい文章
*   **項目名**: この記事に必ず盛り込みたい文章（任意）
*   **UI**: 中くらいのテキストエリア1つ
*   **使い方イメージ**:
    *   自己紹介や肩書き（例：「フリーランス歴3年、React/TypeScriptを中心に開発しています。」）
    *   サービス紹介・CTA（例：「詳しいご相談はプロフィールのリンクからDMください。」）
    *   具体的なフレーズ（例：「行動してから悩む、を合言葉にしてほしいです。」）
*   **AI側の扱い（仕様）**:
    *   **note用**: 記事本文の自然な位置に原文をほぼそのまま挿入（敬体/常体の微調整は許可）。
    *   **X用**: 可能な範囲でフレーズを含めるか、要素だけ抽出して短く再構成する。

---

### 5-3. 生成フロー（ユーザー視点）
1.  **ネタをざっくり書く**
2.  **目的ボタンを1つ選ぶ**
3.  **雰囲気カードを1つ選ぶ**
4.  （あれば）参考URLと、盛り込みたい文章を入力
5.  **「コンテンツ生成」ボタンを押す**
6.  下に note / X の草案が出るので、そこで微修正して投稿

→ 「ネタ + 目的 + 雰囲気 +（任意でURLとフレーズ）」の4つだけで、AIにイメージを伝える負荷を最小限にしつつ、自分色も出せる設計とします。
